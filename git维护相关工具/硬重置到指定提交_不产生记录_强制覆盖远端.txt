硬重置到指定提交_不产生记录_强制覆盖远端
========================================
脚本：硬重置到指定提交_不产生记录_强制覆盖远端.ps1（单文件，拷贝即可用）


命名对照（本目录两类回退）
--------------------------
1) 本脚本（无新记录 / 改写历史）
   硬重置到指定提交_不产生记录_强制覆盖远端.ps1
   = git reset --hard <提交> + git push --force-with-lease
   历史被剪断，不产生新的 commit

2) 有记录回退（配套脚本）
   还原指定提交_产生记录_正常推送.ps1
   = git revert <提交> + git push
   撤销某一个提交的改动，保留原历史，额外产生还原提交，正常推送


做什么
------
1. 运行后展示当前分支最近 20 条提交（哈希 / 日期 / 说明）
2. 按提示手动输入目标：哈希或 HEAD~1 等（不支持序号）
3. 确认 yes 后：回到指定提交，并强制覆盖远程仓库上的同名分支
4. 输入留空则取消，不执行


怎么用
------
1. 把脚本放在目标仓库根目录
2. 直接运行（推荐）：

   powershell -ExecutionPolicy Bypass -File .\硬重置到指定提交_不产生记录_强制覆盖远端.ps1

3. 对照列表输入，例如：
   - 短哈希：a1b2c3d
   - 相对引用：HEAD~1
4. 核对目标提交后输入：yes（大小写均可，如 YES / Yes / yes）

可选：命令行预填默认值（仍会展示列表，回车可采用默认）：

   powershell -ExecutionPolicy Bypass -File .\硬重置到指定提交_不产生记录_强制覆盖远端.ps1 abc1234


注意
----
- 操作前请先备份（拷贝目录或新建 backup 分支），脚本启动时也会醒目提醒
- 动手前先看一眼自己的改动到哪一步了（命令：git status）。分四种常见情况：

    ① 旧文件改了，但还没执行过 git add
       问：要不要管？要。
       会怎样：一跑硬重置，这些修改通常直接没了，很难找回。
       想留住：先 git add 再 git commit；或先 git stash 藏起来，过后再取回。
       不想要：可以继续跑脚本（等于主动丢掉这些修改）。
       脚本：发现还有没提交的改动时，会再问你一句「真的丢弃并继续吗」。

    ② 已经 git add 了，但还没 git commit（也还没 push）
       问：要不要管？要。
       会怎样：和 ① 一样，硬重置后这些内容一般也没了。
       想留住：先 git commit 存成一次本地提交；或先 git stash 藏起来。
       不想要：脚本再确认后继续即可。

    ③ 已经 git commit 了，只是还没 git push 到远程仓库（如 origin）
       问：要不要管？要，但管的是「提交记录」，不是「文件还没收拾好」。
       会怎样：如果你选的「回到哪一次提交」比这些本地提交更早，
              那些还没推上去的提交会从当前分支上消失；
              强制推送后，远程仓库同名分支也会变成剪完后的样子。
       想留后路：先复制一份项目文件夹，或先建备份分支：
              git branch backup/20261011
       若那些提交本来就在你要回到的那次之前（或就是那一次），一般没事。

    ④ 全新文件，从没 git add 过（git status 里常显示为未跟踪）
       问：要不要管？一般不用（硬重置通常不会删掉这种新文件）。
       会怎样：文件多半还在；但脚本仍可能提示「有未提交内容」，看清列表后再决定。
       真要清掉：需要你自己手动删，脚本默认不会替你删。


- 输入目标后直接回车（且命令行也没带默认值）= 取消，什么都不做
- 目标提交必须能解析，且必须在当前分支历史上
- 会改写远程仓库历史，多人共用同一远程仓库时要特别谨慎
- 回退后不要再 git pull，否则可能把旧提交又拉回来
- 仅处理当前所在分支
- 提交说明乱码：脚本已按 UTF-8 读取 git 输出；若窗口字体不含中文，请换「新宋体/Consolas」等
