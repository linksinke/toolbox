还原指定提交_产生记录_正常推送
================================
脚本：还原指定提交_产生记录_正常推送.ps1（单文件，拷贝即可用）


命名对照（本目录两类回退）
--------------------------
1) 无新记录 / 改写历史
   硬重置到指定提交_不产生记录_强制覆盖远端.ps1
   = git reset --hard <提交> + git push --force-with-lease
   分支直接剪到目标提交，不产生新 commit，强制覆盖远端

2) 本脚本（有新记录 / 保留历史）
   还原指定提交_产生记录_正常推送.ps1
   = git revert <提交> + git push
   撤销「某一个提交」的改动，新增还原提交，普通推送


做什么
------
1. 运行后展示当前分支最近 20 条提交（哈希 / 日期 / 说明）
2. 按提示输入要「撤销」的提交哈希或相对引用（不支持序号）
3. 确认 yes 后：撤销那一次提交的改动，并推送到远程仓库
4. 输入留空则取消，不执行


怎么用
------
1. 把脚本放在目标仓库根目录
2. 直接运行：

   powershell -ExecutionPolicy Bypass -File .\还原指定提交_产生记录_正常推送.ps1

3. 对照列表输入哈希或 HEAD 等
4. 核对后输入：yes（大小写均可，如 YES / Yes / yes）

可选预填：

   powershell -ExecutionPolicy Bypass -File .\还原指定提交_产生记录_正常推送.ps1 abc1234


注意
----
- 操作前请先备份（拷贝一份项目文件夹，或新建 backup 分支），脚本启动时也会提醒
- 动手前先看一眼自己的改动到哪一步了（命令：git status）。分四种常见情况：

    ① 旧文件改了，但还没执行过 git add
       问：要不要管？要。
       会怎样：脚本发现后会直接停住，不会替你丢掉这些修改。
       想留住：先 git add 再 git commit；或先 git stash 藏起来，过后再取回。
       不想要：你自己先清掉这些修改，再重新跑本脚本。

    ② 已经 git add 了，但还没 git commit（也还没 push）
       问：要不要管？要。
       会怎样：同样会停住，也不会自动清空。
       想留住：先 git commit 存成一次本地提交；或先 git stash 藏起来。
       处理完再重新跑本脚本。

    ③ 已经 git commit 了，只是还没 git push 到远程仓库（如 origin）
       问：要不要管？不用（不会挡住本脚本）。
       会怎样：本地提交已经存好了，脚本可以正常做「撤销某一次提交」。
       随后：脚本成功后会 push 到远程仓库；你还没推上去的那些本地提交，一般也会一并推过去。

    ④ 全新文件，从没 git add 过（git status 里常显示为未跟踪）
       问：要不要管？要。
       会怎样：脚本也会因此停住；不会删掉这些新文件，但要求你先处理好再继续。
       想先搁置：git stash push -u（连新文件一起藏起来）
       或：先把新文件挪走/删掉（慎用），再跑脚本

  对比：本脚本遇到 ①②④ 是「停住、不帮你清」；
        硬重置脚本遇到 ①② 是「确认后会直接丢掉」。
- 本脚本只撤销「某一个提交」的改动，不是把整个项目时光倒流到很早以前
- 若要把历史剪断并强制覆盖远程仓库，请用硬重置脚本
- 若中途提示冲突：可手动解决后继续，或执行 git revert --abort 放弃这次还原
- 只处理你当前所在的分支
- 若提交说明乱码：换个支持中文的控制台字体（如新宋体）再看
